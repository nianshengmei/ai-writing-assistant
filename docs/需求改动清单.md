## 一、贯穿全局的 5 条原则

| # | 原则 | 具体约束 |
|---|---|---|
| P1 | **禁止覆盖** | 任何 AI 产出不得直接替换已有记忆/设定。必须完整保留原内容，只做增补、修正，输出「整合后的完整条目」。现有一键覆盖点全部整改 |
| P2 | **双保险整合** | 提示词内强制「整合保留原记忆」＋ 落盘前并排对照确认弹窗（原文 / AI 建议 / 整合结果，可编辑、可逐项勾选）。**不保留历史版本** |
| P3 | **一键 AI 全部弹窗化** | 所有 AI 入口改为「弹窗 → 提示词可见可编辑（System / User）→ 点确定才触发」。弹窗**顶部为确定按钮**，下方为可编辑提示词区 |
| P4 | **提示词按功能持久化** | 编辑结果按功能 key 全局持久化，提供「恢复默认」；不再「仅本次生成生效」 |
| P5 | **分组执行 + 全链路可追溯** | 单次上下文容纳得下的合并成一次调用，超出的分次跑再汇总；弹窗显示分组与预计调用次数；所有 AI 调用（含非正文类）落盘记录 |

所有 AI 调用的模型选择沿用 `useFeatureModel`，新功能需补 feature key。

## 二、决策记录（已拍板）

| # | 议题 | 决策 | 落地解读 |
|---|---|---|---|
| 1 | 50 章记忆 | 用每章总结压缩，分几部分，能一次跑的一次跑、不能的分次 | 数据源只用 `recap.json` 逐章摘要（100~200 字/章），**不重读正文**；每 10 章一组做一次压缩调用，50 章 = 5 组 |

| 3 | 大纲对话落盘 | 肯定要落盘，讨论场景模型上下文必须有 | 历史按作品落盘，每轮携带全量 messages 给模型；超长时滚动摘要 |
| 4 | 预测「已改过」分支 | 直接 | 跳过预测弹窗，**仍走提示词确认弹窗**再生成（保住 P3） |
| 5 | 预测窗口 | 下一章 | 只预测 1 章；每次采纳后刷新，新预测须整合上一章预测中尚未兑现的内容 |
| 6 | 小说提取范围 | 不止 7 个，含自定义标签，所有标签一起全提取 | 导入小说 → 7 个内置页签 + 用户自定义标签种类，一次性全量提取 |

| 8 | 整合形态 | 提示词 + 弹窗 | 双保险，**不保留历史版本**；砍掉 `history[]` 字段 |
| 9 | 提示词编辑 | 功能持久化 | 按功能 key 全局存 `prompts.json` + 恢复默认 |
| 10 | 风格提炼 / 测试连接 | 都可以 | 两者均纳入统一弹窗；风格库三段提示词也改为持久化 |
| 11 | 首章边界 | 生成第 1 章不应有后文预测，没法预测 | 判定条件泛化为「是否已有已采纳前序章节 + 预测记录存在」；首章、跳章写、预测被删空一律短路 |

**默认项**（未明确指定，按此执行，不阻塞开发）：
- 大纲对话按**作品一份**历史，非每章一个线程；讨论时可指定章节上下文。
- 提示词持久化**全局作用域**，非按作品隔离。
- 7 类页签中偏主观的「作者要求 / 后文预设」，小说提取结果同样需经整合确认弹窗后才落盘。

## 四、需求明细（按模块）

### A. 世界观导入小说 + 自定义标签种类

**目标**：世界观页支持导入 txt/md 小说文件；从小说中一次性提取**所有标签**（7 个内置页签 + 用户自定义标签种类）的记忆；标签种类可手动增/改/删；内容可手动填写。

**改动点**
- `MemoryPanel.tsx` 世界观 tab（`207-275`）：新增导入区（文件选择 + 拖拽 + 字数/分块提示）。复用 `StyleLibraryModal.tsx:141-149 / 259-306` 的现成范式，`<input type=file>` + `File.text()` 已验证可用，**无需新增 Rust command**。
- 类别硬编码两处（`MemoryPanel.tsx:231`、`244` 的 `["地点","势力","规则","物品","体系","其他"]`）改为从持久化清单读取；新增「+ 新增种类 / 重命名 / 删除」，删除时已有条目的归属需定义规则（建议回落到「其他」并提示）。
- `types.ts` 新增类别类型；`library.ts` 新增 `listWorldviewCategories/saveWorldviewCategories`，`createWork`（`92-106`）初始化，旧作品读不到时给默认值；新增 `memory/worldview-categories.json`（按作品）。
- `context.ts` 新增 `buildExtractAllMessages`：输出按「7 个内置页签 + 自定义类别」分组的结构化 JSON（每类若干条 `{category,name,content}` 等），配公共 `parseJsonLoose`（可从 `StyleLibraryModal.tsx:51-61` 抽出）；长文本按 8000 字分块、多块结果合并去重。
- `context.ts:116` 的 `pickRelevant` 用 `w.category` 渲染，自定义类别自动生效，**无需改动**。

**验收**：导入长篇小说后能分块跑完；7 类 + 自定义类别都有提取结果；结果逐类经整合确认弹窗后才落盘；类别增删改在重启后保持；旧作品打开不报错。

### B. 采纳后的多类记忆更新（含 50 章记忆、全文脉络、后文预测）

**目标**：「采纳」不再只生成前情，而是**更新/补充**主角、配角、世界观、前情、伏笔、50 章记忆、全文脉络，并在有正文依据时生成后文预测。

**改动点**
- `WritingDesk.tsx:253-276`：拆成「✓ 采纳为正式章节（只转正）」+「更新本章记忆」（显式按钮，走弹窗）。状态文案 `260/270/273` 与 `MemoryPanel.tsx:402-405` 的「系统自动维护」说明同步修改。
- 新增统一「记忆更新确认」弹窗：按分组列出更新项，默认全选，可取消勾选；每项并排展示原文 / AI 建议 / 整合结果，可编辑；显示分组与预计调用次数；点确定才执行；单组失败可单独重跑，不阻断章节转正。
- `context.ts` 为每类新增 `build*UpdateMessages(existing, 本章正文, 已有记忆)`，System 强制「完整保留原设定，只增补/修正，输出整合后的完整条目」，结构化 JSON 输出。
- **50 章记忆**：以 `recap.json` 逐章摘要为数据源，每 10 章一组压成「段摘要」；产物与全文脉络滚动更新，**不覆盖原章摘要**。生成时分层注入：近 15 章详细摘要 + 16~50 章段摘要 + 全文脉络。给 `assembleGeneration` 新增对应 section。
- **全文脉络**：新建 `memory/story-arc.json`（主线阶段、重大转折、人物关系演变），作为独立 section 注入 `assembleGeneration`。
- 建议分组（满 50 章约 9 次调用）：A 设定类（主角+配角+世界观+自定义标签，1 次）｜B 前情摘要+伏笔表（1 次）｜C 50 章压缩（最多 5 次）｜D 全文脉络（1 次）｜E 后文预测（1 次，首章采纳时首次出现）。

**验收**：采纳后不自动调用任何 AI；点更新才跑；所有写入均为整合结果、原记忆不丢失；50 章压缩不读正文；提示词注入分层生效；分组失败可重跑。

### C. 大纲改为 AI 对话窗口

**目标**：大纲可与 AI 多轮互动讨论，敲定后生成大纲；也可手动编辑。

**改动点**
- 新增 `OutlineChat.tsx` + `outline-chat.json`（按作品落盘）：多轮消息 + 流式回复，可清空重开；每轮把全量 messages 作为上下文传给模型，超长时滚动摘要。
- `context.ts` 新增 `buildOutlineChatMessages(history, 记忆bundle)` 与 `buildOutlineFinalizeMessages`（把讨论结论 → 结构化章节标题 + 细纲 JSON）。现有 `buildOutlineProposeMessages`（`216-237`）只吃最近 10 章细纲 + 8 条前情，可保留为对话内快捷指令。
- 「敲定并生成大纲」走统一弹窗确认提示词后写回 `outline.json`；**已有章节细纲必须整合保留**，不得整份覆盖。
- 保留现有 textarea 手动编辑（失焦即存），与对话区并存；`OutlinePanel.tsx:64-70` 的 `adopt` 直接覆盖细纲需改为整合。

**验收**：刷新后对话历史仍在且继续作为上下文；敲定生成的细纲不冲掉已有章节；手动编辑与对话生成可混用。

### D. 后文预测 + 生成前判定链（含首章短路）

**目标**：新增 AI「后文预测」（只预测下一章）；生成下一章前判断预测是否被作者修改过，未修改则弹窗预览/修改 → 确认提示词 → 才生成。

**改动点**
- 与「后文预设」分离：预设 = 作者手填规划（保留原语义），预测 = AI 自动生成推测。新建 `memory/future-prediction.json`，字段含 `sourceChapterId`、`generatedAt`、`editedAt`、`reviewedAt`、`content`。
- 预测唯一出生点 = **采纳第 1 章后的记忆更新**（E 组）；每次采纳后刷新，整合上一章未兑现内容（不保留历史版本）。
- `WritingDesk.tsx` 生成入口前置判断 `已有已采纳前序章节 && 预测记录存在`：
  - 否（首章 / 跳章写 / 预测被删空）→ 跳过预测环节，直接进提示词确认弹窗；**不自动补生成**，仅提示「暂无后文预测，可在记忆库手动填写或直接生成」。
  - 是 → 判断 `editedAt` vs `generatedAt`；未修改 → 弹窗①预览/编辑预测 → 弹窗②确认提示词 → 生成；已修改 → 直接进弹窗②。
- `context.ts` `assembleGeneration` 新增「后文预测」section 且**条件渲染**（无预测时整段不输出，不是显示「暂无」）；现有「后文预设」section 保留，首章照常注入、不弹窗。预测弹窗内建议展示相关章节细纲供对照。
- 预测改动写回后同步进注入内容，并注明「与作者意图冲突时以作者修改版为准」。

**验收**：第 1 章生成全程无预测相关 UI、提示词无预测 section；第 2 章起按分支正确弹窗；预测被删空不自动重生；作者手填预设不受影响。

### E. 统一提示词确认弹窗

**目标**：所有 AI 入口统一为「顶部确定按钮 + 下方可编辑提示词」的弹窗，提示词按功能持久化。

**改动点**
- 以 `WritingDesk.tsx:551-592` 为模板抽 `src/components/PromptConfirmModal.tsx`：顶部确定按钮 + System/User 两个可编辑框 + 恢复默认 + 取消 + 模型选择 + （批量时）分组与调用次数展示。
- 新建 `src/lib/prompts.ts` 收拢散落的提示词常量（`context.ts`、`llm.ts:78-83`、`WritingDesk.tsx:31-35`、`StyleLibraryModal.tsx:17-20`）；新增 `prompts.json` 全局持久化 + `loadPromptOverrides/savePromptOverride`。
- `context.ts` 所有 `build*Messages` 补 `systemOverride/userOverride`（风格库三个已有 systemOverride，User 仍不可改）。
- `runSelectionOp`（`WritingDesk.tsx:290-340`）：润色/扩写/重写改为先存选中快照再开弹窗，确定后才 `streamChat`；编辑期间正文可能变动，需校验 selection 或提示重新选择。

**验收**：任一入口均不直接触发 AI；编辑后的提示词刷新仍生效；恢复默认可还原；批量入口显示调用次数。

### F. 前情记忆手动化 + 可编辑

**目标**：文章转正后「生成前情记忆」改手动触发；前情记忆支持手动填写、编辑、删除。

**改动点**
- 采纳与摘要生成解耦（见 B），手动触发走统一弹窗，提示词可见可编辑；已有摘要作为「必须整合保留」注入 `buildRecapMessages`（`context.ts:162-170`）。
- `MemoryPanel.tsx` recap tab 改为可编辑 + 保存/删除；`library.ts` 补 `saveRecapEntry/deleteRecapEntry`（现只有 `appendRecap`）。
- 写作台加软提醒「本章前情记忆未生成」，避免下一章上下文缺失。

**验收**：采纳后不自动出摘要；手动生成需确认弹窗；前情条目可增删改且重启保持。

## 八、完整写作闭环

```
大纲对话讨论 → 敲定并生成大纲（或手动编辑）
  → 点「生成本章」→ 前置判断有无预测依据
      ├ 无（首章/跳章/删空）→ 提示词确认弹窗 → 生成正文
      └ 有 → 预测被改过？
            ├ 否 → 弹窗①预览/修改预测 → 弹窗②确认提示词 → 生成正文
            └ 是 → 弹窗②确认提示词 → 生成正文
  → 润色/扩写/重写（选区弹窗）
  → ✓ 采纳为正式章节（只转正，不调 AI）
  → 手动点「更新本章记忆」→ 分组批量整合更新
      （主角/配角/世界观/自定义标签｜前情/伏笔｜50 章压缩｜全文脉络｜后文预测）
  → 预测刷新，供下一章使用
```

## 九、风险与注意事项

- **Token 预算**：50 章分层注入约 4000 字（近 15 章 ≈ 2250 + 5 段段摘要 ≈ 1000 + 脉络 ≈ 500），需与其他 section 合计核算，超限时优先裁减段摘要。
- **分组执行**：单次合并虽省调用，但失败影响面大；需支持单组重跑与部分结果落盘。
- **选区操作**：润色/扩写弹窗打开期间正文可能被编辑，落笔前必须校验 selection 有效性。
- **旧作品兼容**：所有新增 JSON 读取需兜底默认值，避免历史作品打开即报错。
- **模拟层一致性**：浏览器调试模式走 `storage/idb.ts` 路径映射，新增文件需同步，否则桌面端与浏览器端行为不一致。
- **首章语义**：预测 section 条件渲染（整段不出现），与「后文预设」（可显示「暂无」）区分清楚，勿混为一谈。
